# Fitness

Мобильный трекер тренировок по согласованному графитовому макету с лаймовыми акцентами.

Приложение: https://fitness-valera.marchenkovy99.chatgpt.site

## Возможности

- Две полные тренировки А/Б с программой пользователя: 6 и 7 силовых упражнений. Разминка и заключительная ходьба показаны отдельно.
- Подходы и повторения сохраняются для каждой тренировки отдельно, в том числе для общего упражнения «Жим от груди».
- Статусы «Не отмечено», «Выполнено», «Пропущено»; повторное нажатие снимает отметку. Отметки разделены по тренировке и локальной дате устройства.
- Библиотека с поиском, просмотр упражнения, создание и редактирование; произвольные области тела и описание.
- Обложки из файла или по прямой http/https-ссылке; загруженные фотографии уменьшаются перед сохранением.
- Черновики формы, локальное сохранение между открытиями, экспорт и восстановление JSON-копии.

Локальная копия хранится в localStorage конкретного браузера и адреса. После входа упражнения, обложки, календарь и веса синхронизируются с Supabase. Облачная синхронизация включается после входа в «Упражнения → Облачная синхронизация». При очистке данных браузера потребуется резервная копия. Хранилище ограничено; ошибки сохранения отображаются явно. Удалённые фото требуют доступной ссылки. Отметки не переносятся автоматически на следующий день.

Назначения и описания перенесены из программы пользователя. Обложки сгенерированы и служат только иллюстрациями, не инструкцией по технике. Дополнительные инструкции не добавлены. Румынская тяга сохранена с условием про поясницу и уверенную технику.

## Календарь и веса

У каждого упражнения в тренировке есть поле веса в кг. Поддерживаются десятичные точка и запятая, а также нулевой вес. Значения сохраняются сразу, отдельно для тренировки А/Б и даты. Одна запись каждого типа тренировки в день.

Под списком упражнений находится отметка «Тренировка выполнена». Она записывает в календарь состав занятия, названия, описания, подходы, повторения, веса и индивидуальные статусы. Неотмеченные упражнения не засчитываются автоматически. В календаре можно выбрать день, открыть тренировку и раскрыть описание каждого упражнения. Внесённые позже изменения программы не переписывают исторический состав. Явные изменения сегодняшних весов и статусов отражаются в уже завершённой записи.

Копии JSON содержат календарь и веса. Данные первой версии автоматически дополняются новыми полями, существующие упражнения и отметки сохраняются.

## Запуск

Для сборки нужны Node.js 22+ и `npm ci`, затем `npm run build`. Содержимое `dist/` обслуживается любым статическим HTTP-сервером. Для разработки можно запускать сервер в `dist/`. Нужен любой статический HTTP-сервер, например `python3 -m http.server 8080`. Открыть `http://localhost:8080`. SDK Supabase закреплён в package-lock.json и включается в сборку локально, без внешнего CDN. Прямое открытие `index.html` через file:// не поддерживает ES-модули.

Проверки: `npm test` и `npm run check`. Сборка для хостинга: `node scripts/build.mjs` (выход в `dist/`). Файлы используют относительные пути и подходят для GitHub Pages, включая подкаталог `/Fitnes/`.

На iPhone можно добавить страницу на экран «Домой» через меню «Поделиться» Safari. Для загрузки приложения нужен интернет; автономная загрузка оболочки без сети в этой версии не реализована.

## Проверки первой версии

Автоматически проверены состав программы, сохранение, разделение отметок, редактирование общего упражнения и валидация импорта/обложек. Синтаксис всех JS-модулей проверен Node.js. Полноценная визуальная и сенсорная проверка в мобильном браузере пока не проведена.


## Облачная синхронизация

В «Упражнения → Облачная синхронизация» войдите с почтой и паролем. На каждом устройстве нужен один и тот же аккаунт. Auth общий с существующим Supabase-проектом Trecker; данные Fitness лежат отдельно в fitness_sync_state. Существующие таблицы и настройки Trecker не менялись. Для нового аккаунта может потребоваться подтверждение почты по письму Supabase. Подтверждение может перенаправить на основной адрес существующего проекта; после него вернитесь в Fitness и войдите.

Первое подключение загружает имеющиеся локальные результаты в пустое облако. Новое устройство с исходной программой получает облачную копию. При расхождении непереданных локальных данных и облака требуется явный выбор. До замены копии скачивается резервный файл. Версия проверяется атомарно при записи; устаревшая копия не перезаписывает более свежую. Без сети изменения остаются локально, повторная синхронизация идёт после восстановления сети или вручную. Обновления проверяются при фокусе и раз в 30 секунд. Не закрывайте страницу до статуса «Синхронизировано», если нужна немедленная передача.

Доступ ограничен RLS по auth.uid(). Клиент содержит только publishable key. service_role и серверных секретов в исходниках нет. Эталон схемы — supabase/fitness-schema.sql, миграция fitness_cloud_state применена к проекту.

При переходе с прежнего адреса на GitHub Pages сначала синхронизируйте данные на старом адресе, затем войдите тем же аккаунтом на новом. Локальное хранилище разных доменов не общее.

## GitHub Pages

Workflow .github/workflows/pages.yml проверяет, собирает и публикует dist при push в main. В настройках репозитория Settings → Pages источник должен быть GitHub Actions. Само включение Pages требует доступа к настройкам GitHub; workflow не использует личный токен для изменения настроек.


## Оформление в стиле «Пульса» (20.10.2026)

Обновлённый интерфейс использует светлые карточки, коралловые акценты, симметричную компактную нижнюю панель и более равномерные отступы. Тёмная тема и автоматическое переключение по системной теме сохранены. Переключение экранов и открытие диалогов сопровождаются короткими анимациями, которые отключаются при системном уменьшении движения. Разметка и модель тренировок, дополнительные программы, календарь, веса, экспорт и облачная синхронизация сохранены. Стили вынесены в `pulse-inspired.css` и применяются поверх существующего оформления.
